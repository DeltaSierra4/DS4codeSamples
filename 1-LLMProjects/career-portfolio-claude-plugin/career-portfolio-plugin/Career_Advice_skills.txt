# Career Portfolio Builder — Plugin

A Claude plugin that turns the `Career_Advice_*` source files into an interactive, dialogue-driven document builder. It produces five tailored job-search documents for a career-changer moving from AI engineering into events / guest-experience / community / fashion / AI-program roles.

## What it builds

| Document | Skill | Output |
|---|---|---|
| Master accomplishment inventory | `accomplishment-inventory` | `.md` |
| Resume A — non-technical roles | `resume-a` | `.docx` + `.pdf` |
| Resume B — AI/tech-adjacent roles | `resume-b` | `.docx` + `.pdf` |
| Portfolio A — events / guest experience / community / fashion | `portfolio-a` | `.pdf` + `.html` |
| Portfolio B — AI/tech events / community / education / programming | `portfolio-b` | `.pdf` + `.html` |

## How to use it

Run **`/career-portfolio`** (or just invoke the `career-portfolio` skill). It will:

1. Ask where your information lives, with three options — **current directory**, **a different path** (it then asks you for the path), or **something else** (it then asks how you'd like to point it to your info).
2. Read your top-level `Career_Advice_*` files and any of your own data to pre-fill what it can.
3. Ask which document(s) you want.
4. Hand off to the matching document skill, which runs a short tailoring dialogue and writes the files (default output: a `generated_documents/` subfolder).

### Commands

| Command | What it does |
|---|---|
| `/career-portfolio [doc]` | Orchestrator — resolves the folder, then routes to any document. |
| `/career-inventory` | Master accomplishment inventory (`.md`). |
| `/career-resume-a [role]` | Resume A — non-technical roles (`.docx` + `.pdf`). |
| `/career-resume-b [role]` | Resume B — AI/tech-adjacent roles (`.docx` + `.pdf`). |
| `/career-portfolio-a [role]` | Portfolio A — events/guest-experience/community/fashion (`.html` + `.pdf`). |
| `/career-portfolio-b [role]` | Portfolio B — AI/tech programs (`.html` + `.pdf`). |
| `/career-update` | Re-sync skill templates after a source file changes. |

Each document skill can also be invoked directly by name; it will resolve the folder itself if needed.

### Sample copy is a draft, not verbatim

The templates, summaries, headlines, and case-study copy in each skill's `reference.md` are **illustrative structure, not final text**. The skills draft in your voice and confirm wording with you before finalizing — nothing is printed word-for-word from the reference.

## Keeping it in sync

Templates and tailoring rules are bundled in each skill's `reference.md`, derived from the source files. When you add a new `Career_Advice_*` file (top level only) or change an existing one, run the **`update-career-skills`** skill to re-sync the references. This is deliberately manual — nothing auto-updates.

## Guardrails (enforced by every skill)

Never invent metrics; describe factual scope instead. Keep "Volunteer" labels visible. No sales/quota or public-relations framing. Protect private guest/community/client data. Label concepts and targets as such — never as actual results. **Source precedence:** `Career_Advice_New*` supersedes `Career_Advice_Old` — the removed public-relations and sales/quota roles are never reintroduced.

## Output fidelity

Resumes generate the `.docx` first, then produce the `.pdf` by converting that same file (LibreOffice) so the two never diverge. Portfolios build the `.html` deck first (landscape 16:9, WCAG-friendly contrast/headings/alt-text), then render that same HTML to `.pdf` with a headless browser so the PDF matches the deck page-for-page.

# Accomplishment Inventory — Columns, Rules, and Template

> Source: `Career_Advice_New_resume.txt` ("Create your accomplishment inventory") and reinforced in `Career_Advice_New_portfolio.txt` and `Career_Advice_Old.txt`.

## How to use this reference (read first)

Everything below — the column set, the sample template, and any example phrasing — is **illustrative structure, not verbatim output**. It shows what belongs in the inventory and how to organize it, not the exact words to print. Treat any sample wording as a starting draft to adapt to the user's own voice, and confirm phrasing with the user before finalizing. What should stay stable is the *structure* (the columns), the *honesty rules*, and the *real data the user provides* — never invented sample values.

## Columns to capture (one row per role / event / community)

1. Organization and event
2. Dates
3. Paid or volunteer
4. Your official title
5. Event attendance
6. Number of guests supported
7. Number of appearances or sessions
8. Staff or volunteers supervised
9. Community membership
10. Engagement or participation
11. Budget responsibility
12. Vendors or partners coordinated
13. Travel or itineraries coordinated
14. Problems solved
15. Processes you created
16. Satisfaction or survey results
17. Photos or documents available
18. Permission to publish
19. Reference who can verify the work

## Honesty rules (non-negotiable)

- **Do not invent percentages or results.** If a result was never measured, describe the scope and deliverable instead. Example: *"Created a centralized guest schedule covering 24 appearances across two event days."* That is stronger and more honest than an unverifiable improvement claim.
- Separate **personal** accomplishments from **team** accomplishments. When it was a team effort, phrase it as leading a function within a broader team (e.g., "Led guest-relations operations within a broader event team responsible for programming, production, security, vendors, and attendee services").
- Mark **paid vs. volunteer** on every row; keep "Volunteer" visible for volunteer roles.
- Record whether **photos/documents** exist and whether there is **permission to publish** — the portfolios depend on this.
- Name a **reference** who can verify each entry.

## Data to request from organizations

Prompt the user to ask AMP and TouhouFest for historical data from: registration systems, schedules, surveys, Discord insights, social-media analytics, and event reports. Anything still unmeasured after that should be recorded as factual scope, not guessed.

## Metrics families to consider (pull relevant ones into rows)

- **Guest-relations:** number of guests; guest appearances; itineraries/schedules; % of appearances completed; response time to guest inquiries; number/type of last-minute changes; guest satisfaction; accessibility requests fulfilled; volunteers supervised; issues resolved.
- **Event:** registrations and attendance; attendance rate; session participation; schedule adherence; check-in time; attendee satisfaction; budget variance; number of vendors/partners; number of incidents; repeat participation.
- **Community:** total members; active members; membership growth; post reach/engagement; event-channel participation; response time; event registrations from community links; member retention; moderator workload; community sentiment/survey results.
- **AI / technical-program:** number of users/stakeholders; project delivery time; adoption; process time saved; workshop attendance; completion rates; knowledge improvement; documentation usage; satisfaction scores; number of speakers/technical sessions supported.

# Master Accomplishment Inventory

The inventory is the single source of truth the résumés and portfolios draw from. Its purpose is to capture, in one place and honestly, the scope and results of every role, event, community, and professional accomplishment — so later documents can be assembled and re-tailored without re-interviewing the user each time.

Read `reference.md` in this skill folder for the column set, honesty rules, and the output template before you build anything. Treat its template and any sample wording as **illustrative structure, not verbatim output** — the columns and honesty rules are what matter; adapt any phrasing to the user's voice and confirm before finalizing.

## Workflow

1. **Confirm the source folder and output location.** If invoked directly (not via the `career-portfolio` orchestrator), first resolve the source folder using the three-option dialogue described in the orchestrator skill (current directory / a different path / something else). Read any `Career_Advice_*` files and the user's own data files there to pre-fill what you can. When `Career_Advice_*` files disagree, `Career_Advice_New*` supersedes `Career_Advice_Old`. Default output location is `generated_documents/` inside the source folder.

2. **Pre-fill from what exists.** Scan the folder for event stats, spreadsheets, schedules, survey exports, social/Discord analytics, and notes. Populate every column you can from these before asking the user anything.

3. **Interview to fill gaps — one entry at a time.** For each role/event/community, walk through the columns in `reference.md`. Ask only for what you couldn't pre-fill. Keep questions grouped and light; use `AskUserQuestion` where a small set of choices fits, otherwise ask in plain text. Prompt the user to request historical data from AMP and TouhouFest (registration systems, schedules, surveys, Discord insights, social analytics, event reports) for anything unmeasured.

4. **Enforce honesty.** Never invent percentages or results. If a value was never measured, record the factual scope/deliverable instead (e.g., "Created a centralized guest schedule covering 24 appearances across two event days"). Mark each row's paid/volunteer status, whether photos/documents exist, whether there is permission to publish, and who can verify it.

5. **Write the Markdown file.** Follow the template in `reference.md`. Use one row per role/event in the main table, then an expandable notes block per entry for longer detail (problems solved, processes created). Save as `Master-Accomplishment-Inventory.md` in the output folder.

6. **Verify before finishing.** Re-read the file and confirm: every column is present, no fabricated metrics slipped in, volunteer rows are labeled, and unmeasured items are described as scope rather than as invented results. Then tell the user where the file is and what still needs data (flag empty cells they should chase down).

## Output format

Markdown only. The file must be easy to keep updating by hand, so prefer a clean table plus short per-entry note sections over dense prose.

# Career Portfolio Builder — Orchestrator

This skill coordinates the production of five job-search documents for a career-changer, using the `Career_Advice_*` files as the source of truth for templates, tailoring rules, and candidate background:

1. **Master accomplishment inventory** → skill `accomplishment-inventory` (Markdown)
2. **Resume A** — non-technical events/guest-experience/community/fashion roles → skill `resume-a` (.docx + .pdf)
3. **Resume B** — AI/tech-adjacent events/community/education/programming roles → skill `resume-b` (.docx + .pdf)
4. **Portfolio A** — events, guest experience, community, fashion → skill `portfolio-a` (.pdf + .html)
5. **Portfolio B** — AI/tech events, community, education, conference programming → skill `portfolio-b` (.pdf + .html)

Your role is to run a short intake dialogue, then hand off to the right document skill(s). Do not produce the documents yourself here — the individual skills own their templates and tailoring rules.

## Step 1 — Resolve the source folder (ALWAYS do this first)

Every document is built from information in a source folder (the `Career_Advice_*` files plus any of the user's own background/data files). Before anything else, determine which folder to use by asking the user with the `AskUserQuestion` tool. Present exactly these three options:

- **"Current directory"** — the folder Claude is currently working in / the connected folder. Resolve this to the working directory or the user's selected folder.
- **"A different path"** — if chosen, in the **next step** ask the user to type the absolute path to the folder, then use it.
- **"Something else"** — if chosen, in the **next step** ask the user an open question ("How would you like to point me to your information?") and follow their free-form response (e.g., they may want to paste content directly, upload files, or name a connector location).

Phrase the question naturally, e.g.: *"Where is the folder with your Career_Advice files and background info?"* with those three options.

After you have a candidate folder, confirm it exists and list what is inside. Verify you can see at least one `Career_Advice_*` file. If the folder is missing or empty, tell the user plainly and re-ask rather than guessing.

## Step 2 — Load shared context

From the resolved folder, read the top-level `Career_Advice_*` files (do NOT recurse into subdirectories) to ground yourself in the candidate's background, positioning, salary guidance, target companies, and the "keep sales/PR out" boundaries. Also note any of the user's own data files (event stats, spreadsheets, notes) that could pre-fill document fields. Reading these lets you avoid asking the user for information the files already contain.

**Source precedence (important).** When files disagree, the newer/corrected guidance wins: `Career_Advice_New*` supersedes `Career_Advice_Old`. The Old file still lists public-relations and sales/sponsorship/quota roles that the New file *explicitly removed* — never reintroduce those role types or their framing, even though they appear in Old. If a brand-new `Career_Advice_*` file is present, treat the most recent guidance as authoritative and flag any genuine conflict to the user rather than silently merging.

## Step 3 — Choose the document(s) to produce

Ask the user which document(s) they want, using `AskUserQuestion` with `multiSelect: true`. Offer the five documents above. If the user hasn't yet built a master accomplishment inventory and wants a resume or portfolio, gently note that the inventory is the recommended first step (the source guidance treats it as the foundation the other documents draw from), but let them decide.

## Step 4 — Delegate

For each selected document, invoke the corresponding skill by name, in this recommended order when multiple are chosen: `accomplishment-inventory` → `resume-a` → `resume-b` → `portfolio-a` → `portfolio-b`. Pass along:

- the resolved source folder path,
- the output folder (default: a `generated_documents/` subfolder inside the source folder — create it if needed),
- any candidate facts you already gathered, so the sub-skill doesn't re-ask.

Each document skill runs its own tailoring dialogue and writes its output files. After each completes, briefly confirm what was produced and where.

## Guardrails carried through every document

These come straight from the source guidance and every downstream skill must honor them:

- **Never invent numbers or results.** If a metric was never measured, describe the scope/deliverable factually instead (e.g., "Created a centralized guest schedule covering 24 appearances across two event days").
- **Label honestly.** Keep "Volunteer" visible beside volunteer titles. Use the labels *Actual Work — Volunteer*, *Actual Work — Paid*, *Reconstructed and Redacted Work Sample*, *Independent Concept Proposal*, and *Illustrative Target — Not an Actual Result* consistently.
- **No sales or PR framing.** Exclude quota/pipeline/OTE/business-development language and public-relations/media-relations framing. Guest relations is an operational hospitality function, not PR.
- **Protect private information.** Never include private guest data, phone numbers, addresses, travel/hotel details, private messages, unpublished contracts, or client-confidential material.
- **Tailor, don't fabricate.** Adapt emphasis and ordering to the target role using each skill's tailoring rules; delete any sample bullet the user did not actually perform.
- **Reference copy is a sample, never verbatim output.** The templates, sample summaries, headlines, and case-study sentences in each skill's `reference.md` show structure and the kind of content expected — they are drafts to be reworded in the user's own voice, not text to print as-is. Always draft, show the user the wording, and revise to their preference before finalizing.

## Updating the plugin when source files change

If the user adds a new `Career_Advice_*` file to the folder and wants the skills refreshed, that is a separate, manually-invoked task — point them to (or invoke) the `update-career-skills` skill. This orchestrator does not auto-refresh templates.

# Portfolio A — Structure, Case Studies & Tailoring Rules

> Source: `Career_Advice_New_portfolio.txt` (Portfolio A sections) and `Career_Advice_New_resume.txt` (portfolio case studies). 8–12 landscape (16:9) pages. Anything in `[brackets]` needs real data. Never present concepts or targets as actual results.

## How to use this reference (read first)

The cover text, profile copy, case-study titles, and all sample sentences below are **illustrative sample copy, not verbatim output**. They show the intended page structure, ordering, and the kind of content each page should hold — not the exact words to print. Treat every sample phrase as a first draft to rewrite in the user's own voice, and confirm wording with the user before finalizing. What stays stable: the page structure and ordering, the honesty labels, the privacy include/exclude rules, and the user's real data — not the sample phrasing.

## Page layout rules (every page)

- A clear title; one central point; a photo/diagram/timeline/redacted work sample; 3–5 short bullets; metrics where available; the candidate's exact role; and an honesty label.
- Understandable from headings, captions, and metrics alone. No dense paragraphs.
- Honesty labels (use consistently): **Actual Work — Volunteer**, **Actual Work — Paid**, **Reconstructed and Redacted Work Sample**, **Independent Concept Proposal**, **Illustrative Target — Not an Actual Result**.

## Default cover

> **YOUR NAME** — Guest Experience, Community Programs & Live Events
> Japanese Fashion • Fandom Communities • Event Operations
> "Creating organized, welcoming experiences for passionate fan and fashion communities."
> [Email] | [LinkedIn] | [City, State] | one approved event photo

Avoid a cosplay portrait as the main image unless it shows the candidate professionally hosting/facilitating.

## Minimum-viable 8-page structure (default)

1. Cover
2. Professional profile and career highlights (+ four proof tiles: 10 years community leadership; 5 years AMP event involvement; 12+ events hosted/supported; 6 years professional consulting — use only substantiable numbers)
3. TouhouFest case study — situation, role, scope
4. TouhouFest workflow and artifacts — actions, artifacts, results
5. AMP community-outreach case study
6. AniMarketPlace (or other) case study
7. EGL traveling-event proposal (labeled *Independent Concept Proposal — Not Yet Produced*)
8. Testimonials and contact

Optional added pages (to reach 10–12): event-delivery method page (before/during/after + guest-lifecycle diagram); event operating toolkit (guest intake template, event brief, run of show, incident escalation guide, post-event report).

## Case-study rules

Every case study answers: (1) What was the event/program? (2) Who was it for? (3) Why did it matter? (4) Exact responsibility? (5) Constraints/problems? (6) Actions personally taken? (7) Work samples that prove it? (8) Result? (9) What to improve next time?

For team efforts: "I led guest-relations operations within a broader event team responsible for programming, production, security, vendors, and attendee services."

### Flagship — TouhouFest Guest Experience
Situation/role/scope page: event overview; responsibility; scope at a glance (guests supported, appearances coordinated, event days, staff/volunteers led, attendees); main challenge. Actions/results page: what I did (coordinated communications/schedules/credentials/travel/hospitality/accessibility — retain only what's true; created master schedule/contact sheet/briefing/intake form/escalation process; briefed [X] volunteers; served as escalation point; documented improvements); results using verified metrics, or factual deliverables if no numbers (e.g., "Produced one centralized guest schedule covering 24 appearances across two event days"); evidence (redacted schedule, blank intake form, volunteer briefing, timeline, redacted run of show, workflow diagram, approved photo, leadership testimonial).

### AMP Community Outreach
Challenge; role (Facebook/Discord comms, representing AMP in communities, coordinating announcements with leadership, collecting feedback, supporting online-to-offline participation); results (community size, campaign reach, event-channel participants, communities/partners contacted, inquiries answered, verified engagement change); evidence (redacted content calendar, announcement workflow, sample approved announcement, moderation/escalation flowchart, anonymized engagement report, event FAQ). If no analytics, show the system built.

### AniMarketPlace (or other actual event)
Pick one event with a clearly defined responsibility; focus on ONE problem solved (hosting, attendee flow, community programming, guest coordination, volunteer management, vendor communication, schedule recovery, on-site issue resolution). Not a photo album — each image explains a decision, responsibility, or outcome.

### Proposed EGL Traveling Experience — "EGL Across Cities"
Label *Independent Concept Proposal — Not Yet Produced*. Business/audience need; proposed audience; proposed program (sample run of show); guest/attendee experience (pre-event info, accessibility/dietary process, briefings, newcomer orientation, photography consent, code of conduct, quiet area, feedback survey); sample success TARGETS clearly labeled as targets (e.g., 200 registrations/city, 85% attendance, 4.5/5 satisfaction, 90% of items starting within 5 min, 25% newcomers, accessibility requests answered within 2 business days); evidence to create (event brief, run of show, venue scorecard, audience journey map, guest comms plan, sample budget, staffing plan, risk register, post-event survey).

## Per-role customizations (change cover, page order, and one or two specialized pages only)

**A1. Experiential / Brand Experience Manager** — Order: Cover → Profile → Event-delivery method → strongest audience-experience case (AniMarketPlace) → TouhouFest → EGL experience → Audience journey + run of show → Budget/risk/measurement → Testimonials → Contact. Emphasize audience experience, event concept, brand alignment, production planning, vendors/venues, budget stewardship, measurement.
