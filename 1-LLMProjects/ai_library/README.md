# ai-lib

Seven skills that turn a folder of PDFs into a document library an agent can actually answer
from — AI, LLM, data science, math/science/technology/cybersecurity, and whatever else was
worth keeping.

The library is plain markdown on disk. Nothing is indexed into a vector store, nothing needs a
server, nothing needs a pip install. The retrieval layer *is* the directory layout, shaped so
that one subagent can become the master of one topic without ever reading another topic's
pages.

Most of what lands here will be a blog post saved as a PDF, not a peer-reviewed paper. The
contract is built for that: authorship and venue are optional, `publication_type` and
`authority` are not, and staleness is a first-class problem because a model announcement from
eighteen months ago is not merely old — read as current, it is wrong.

---

## The skills

| Skill | What it does |
|---|---|
| `/ai-lib-setup` | Scaffolds the library: five directories, the sixteen-node topic tree, the page contract, the taxonomy, the config. Creates no document — a tree of empty leaves is the correct end state. |
| `/ai-lib-ingest` | Reads one PDF or text file into a page of attributed claims, then follows its links **exactly one hop** and quarantines what they say. The engine; everything else reads what it writes. |
| `/ai-lib-refresh` | Finds the page numbers behind `[unlocated]` claims, looks for newer versions, re-checks dead links, triages staleness. |
| `/ai-lib-list` | Builds `output/library.html` — every document by topic, searchable across claim text, every marker rendered distinctly. |
| `/ai-lib-query` | The Agentic RAG search. Fans out one subagent per topic and answers with a citation on every sentence. |
| `/ai-lib-compare` | Two or more documents side by side, benchmark tables joined, disagreements flagged with both locators. |
| `/ai-lib-lint` | Audits every claim for a marker and every capture against its link plan, auto-repairs counts and formats, regenerates `index.md`. |

Set up once, ingest repeatedly, lint after every handful of ingests, and query or compare
whenever. Every skill is standalone; none blocks.

## The taxonomy

Five top-level topics, **fourteen leaves**, and the tree was shaped to that number because the
leaf is the unit of parallelism — one subagent each.

```
topics/
├── ai/                        ~35%  model-agnostic: architectures, RLHF, alignment,
│                                    interpretability, agents, evaluation, theory
├── llm/                       ~35%  model-specific — mostly blog posts, ages fastest
│   ├── claude/  gpt/  gemini/  grok/  qwen/  kimi/  other-models/
├── data-science/              ~15%  statistics, ML engineering, pipelines, MLOps
├── math-sci-tech-cyber/       ~10%
│   ├── math/  science/  technology/  cybersecurity/
└── misc/                       ~5%  real-life material that is none of the above
```

The percentages are **reporting weights, not quotas**. Nothing refuses an ingest because a
topic is over its share; `/ai-lib-lint` reports the drift, and where reality disagrees with
the guess, reality is right. The useful signal is a topic sitting near zero — that usually
means its material is being filed somewhere else.

**`ai` versus `llm/<model>` is the one distinction worth memorizing**, and the test is
mechanical: *delete every model name from the document. Is it still about something?* Yes →
`ai`. No → `llm/<that model>`. "How Claude's constitutional training works" is `llm/claude`.
"Constitutional AI as a method" is `ai`.

## What the library looks like on disk

```
<library-root>/
├── SCHEMA.md              the page contract — copied in at setup, never edited in place
├── AGENTS.md              how to retrieve from and write to this library
├── CLAUDE.md              a pointer plus the live Library Brief
├── index.md               every document by topic (regenerated by /ai-lib-lint)
├── log.md                 append-only, every skill writes here
├── _config/
│   ├── taxonomy.md        which topics exist and what belongs in each — the placement authority
│   └── library-config.md  shares, staleness thresholds, link caps
├── topics/<topic-path>/
│   ├── topic.md               what this topic covers, its themes, its gaps
│   ├── documents/<slug>.md    one page per document — the knowledge
│   └── captures/<doc>__<link>.md   one receipt per depth-1 link followed
├── raw/<topic-path>/      immutable originals
├── synthesis/             saved answers and comparisons
└── output/                HTML, reports, link plans, intermediate json
```

## The four ideas that make it work

**1. Every claim carries a marker, and there are exactly four.**

```
1. Self-supervised critique removes the need for human harmfulness labels. [p. 2] [type: methodological]
2. The approach should generalize to other constraints. [unlocated] [type: forecast]
```

| Marker | Means |
|---|---|
| `[p. 15, Fig 7]` | **this document** says it, there |
| `[unlocated]` | this document says it; the page could not be pinned |
| `[link: <url>, accessed <date>]` | a **depth-1 linked page** says it — not this document |
| `[inference: ...]` | **you** concluded it; the document does not say it |

**A claim with no marker is the one thing this library may not contain.** It is
indistinguishable from a traceable one, and the entire value of a RAG library over documents
is that an answer can be traced. `/ai-lib-lint` reports every unmarked claim at the top of
its report, and **deliberately cannot autofix one** — the only correct fix is to reopen the
source and find the page, and a marker invented to satisfy a linter is worse than the unmarked
claim it replaced.

**2. Links are followed exactly one hop, and the limit is audited rather than promised.**

`extract-pdf.py` reads a source and emits an **authorized link plan** to
`output/_linkplan-<slug>.json` — every URL stamped `depth: 1`, junk filtered, social domains
excluded, capped, and with hyperlink-annotation targets recovered that never appear in the
visible text.

A script cannot do the fetching, so it cannot physically stop a second hop. The limit is made
**auditable** instead: every capture carries `depth: 1` and a `parent_doc`, and `/ai-lib-lint`
checks each capture's URL against its parent's plan. **A capture in no plan is an error —
`CAP-UNAUTHORIZED` — and that is the signature of a second-hop fetch.** Every link found *on*
a fetched page goes in that capture's `## Not taken`, unfetched, which is the audit trail
proving depth-2 links were seen and declined rather than never noticed.

The sanctioned route from depth 2 to depth 1: save that page and ingest it deliberately. That
keeps a human in the loop where the design wants one.

**3. Linked material is quarantined, absolutely.**

Everything harvested from a depth-1 link lives in the document page's `## From Linked Pages`
section and its capture receipt. **Never in `## Key Claims`, never in `## Evidence`, never in
`## Method`, and never carrying a `[p. N]`** — a linked paper has page numbers too, and a
`[p. 4]` on borrowed material makes it indistinguishable from the document's own. The linter
enforces the boundary in both directions: a `[link:]` outside the quarantine and a `[p. N]`
inside it are both errors.

**4. One walker, many consumers; and the arithmetic is Python.**

`lint-library.py` is the only thing that walks the tree. It emits one JSON carrying both the
inventory and the findings, and `index-library.py`, `patch-library.py`, `build-library.py` and
`build-compare.py` all read that JSON. Five scripts that can never disagree about what the
library contains.

The benchmark join in `/ai-lib-compare` is the clearest case for keeping work out of the
model: documents are joined on the **exact** normalized (benchmark, metric) pair, and a
mismatch in reported numbers is flagged as a disagreement with both values, both locators and
both authorities. The join is deliberately exact — fuzzy-matching "MMLU" to its expanded name
would silently equate a 5-shot result with a 0-shot one. That is why the contract demands the
document's own names verbatim.

A fifth, smaller: **ingest resolves; lint flags.** `/ai-lib-ingest` and `/ai-lib-refresh`
settle a conflict at write time and log the decision. `/ai-lib-lint` marks what it cannot
decide and never picks a winner.

## Installing

### As a plugin

```
/plugin marketplace add <path-to>/wiki_v3
/plugin install ai-lib@wikiwiki
```

### As plain skills

```bash
cp -r wiki_v3/skills/ai-lib-* ~/.claude/skills/
```

Every `SKILL.md` resolves its own files with a two-rung ladder — `skills/<name>/scripts/`
first, then `$CLAUDE_PLUGIN_ROOT/skills/<name>/scripts/`, with `assets/` in place of
`scripts/` for `ai-lib-setup` — so the same file works either way with no edit. Four skills
reach into a sibling's `scripts/` by the same ladder, because `lint-library.py` is the
family's single tree walker and duplicating it would mean two walkers that eventually
disagree.

### Requirements

**Python 3.8 or later, and nothing else.** Every script is standard library only: no PyYAML,
no jinja, no requests, no pdfminer. That is deliberate — an ingest skill that needs a pip
install is an ingest skill that fails on a locked-down laptop.

`pdftotext` (poppler-utils) is used for PDFs **if it happens to be on PATH**, always with
`-layout` so a two-column paper does not interleave its columns. Where it is absent, fails, or
the PDF is a scan, `extract-pdf.py` exits **2** and tells the agent to read the file with its
own native reader rather than returning partial text. A plausible mis-extraction of a
benchmark table is worse than no extraction, because either way the number lands in the
library and gets cited.

## The scripts

| Script | Lives with | Role |
|---|---|---|
| `extract-pdf.py` | `ai-lib-ingest` | text out of a PDF or txt, **plus the authorized depth-1 link plan**. Recovers hyperlink-annotation targets invisible in the text. Exit 2 = read it natively |
| `new-page.py` | `ai-lib-ingest` | schema-conformant document / topic / capture skeletons. Refuses an undefined topic, refuses a branch, refuses to overwrite (exit 3) |
| `lint-library.py` | `ai-lib-lint` | the only detector and the only tree walker. Read-only. Emits inventory + findings with a stable `rule`, `severity` and `autofix` per finding, and parses `## Evidence` rows so the join can happen |
| `patch-library.py` | `ai-lib-lint` | the only writer of page fixes. Realigns counts and identifiers to the tree; declines by design anything needing a source reopened or a sentence judged |
| `index-library.py` | `ai-lib-lint` | regenerates `index.md` in taxonomy order. Never walks the tree |
| `build-library.py` | `ai-lib-list` | the browsable catalog. Splits each claim from its marker so the four kinds render distinctly |
| `build-compare.py` | `ai-lib-compare` | the benchmark join and disagreement detection. `--json` emits the computed payload |

All seven are invoked by path and never inlined, retyped or regenerated. Every one takes
`--help`. Exit codes are `0` on success and `1` on a hard error, plus two documented extras
that are not failures: `extract-pdf.py` exits **2** for "this needs your own reader", and
`new-page.py` exits **3** for "that page exists, read it instead". **Findings never affect the
exit code** — a library with 400 violations still exits 0, because the JSON is the report.

## What this library is not

A structured record of what a collection of documents says. Not a substitute for reading them,
not a citation manager, and not an authority in its own right.

A document being here implies nothing about whether it is correct. A first-party announcement
is a marketing artifact as well as a technical one; a preprint has not been reviewed; a blog
post may have been quietly edited since it was captured. The four markers exist so a reader
can always tell what kind of thing they are relying on, and every deliverable names the kind
of source it rests on — flagging an answer that rests on a single document, on sources that
are all first-party, or on a page whose publication date has gone stale.

## Lineage

Three earlier families in this repository. `wiki_v0` (`ddv-wiki-*`) contributed the
LLM-as-librarian pattern and the single-file static HTML build. `wiki_v1` (`int-bpsi-*`)
contributed the discipline: a contract copied byte-for-byte and cited by section number, the
resolve/flag split, the four-tier finding model that reduces an approval gate to one question,
and fan-out written as threshold → partition key → enumerated return contract → hard barrier.
`wiki_v2` (`hiw-*`) contributed the folder-as-unit-of-parallelism, findings with stable rule
ids and severities, a patcher that independently re-verifies before writing, and — from a live
Sonnet/Haiku test — the finding that models fail *conservatively* when the schema forbids
guessing, which is why this contract forbids an unmarked claim rather than merely discouraging
one.

New here: the four-marker provenance system with a linter that proves markers are present; the
depth-1 link plan as an auditable authorization surface rather than an instruction; the
quarantine section enforced in both directions; and a benchmark join exact enough to be
trusted.
